# BuildSure Deployment Notes

This document covers production database setup and migrations. Product architecture remains in `BUILD_GUIDE.md`.

## Database URL

Production and staging should use PostgreSQL through `DATABASE_URL`.

Accepted examples:

```text
postgresql://user:password@host:5432/database
postgres://user:password@host:5432/database
```

`postgres://` is normalized to `postgresql://` by application config for platform compatibility.

Do not commit real credentials.

## New Database Setup

For a new staging or production database:

```text
flask db upgrade
```

Run this with:

- `FLASK_APP=main`
- `APP_ENV=production`
- a valid PostgreSQL `DATABASE_URL`
- a production `SECRET_KEY`

## Migration Commands

Create a new migration after model changes:

```text
flask db migrate -m "describe change"
```

Apply pending migrations:

```text
flask db upgrade
```

Roll back one migration when safe:

```text
flask db downgrade
```

## Existing Databases

Do not run `db.create_all()` in production.

The baseline migration is intended for a new empty database.

For an existing database, first verify that its schema exactly matches the migration baseline. Only after validation, mark it with:

```text
flask db stamp head
```

Do not stamp a database that has not been inspected.

`stamp head` is not the default setup path. Use it only when an existing schema has been reviewed and confirmed equivalent.

## Local SQLite

The existing local SQLite database is not automatically migrated by this sprint.

Development may continue using local SQLite. To test migrations, use a temporary database and run `flask db upgrade` against that temporary `DATABASE_URL`.

Review every future autogenerated migration before deploying it.
